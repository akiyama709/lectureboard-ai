# プライバシー・セキュリティ設計

## 1．保護対象

LectureBoard AIが扱い得る情報には，次が含まれる．

- 講師の音声
- PowerPointスライド
- 未発表研究
- 学生の発言
- 学生氏名や個人情報
- 講義文字起こし
- 講師の手書き
- AI板書
- APIキー

これらを通常のアプリログと同じように扱ってはならない．

## 2．既定のデータ方針

| 項目 | 既定値 |
|---|---|
| 音声の録音保存 | OFF |
| PowerPoint映像の保存 | OFF |
| 全文文字起こし保存 | OFF |
| AI板書保存 | ON |
| 講師手書き保存 | ON |
| 外部AIへの送信 | OFF |
| 利用分析・テレメトリ | OFF |
| クラッシュログへの講義本文 | 禁止 |

## 3．権限

### 画面収録

講義開始時に，なぜ必要かを説明した後で要求する．選択したPowerPointウィンドウだけを取得する．

### マイク

音声認識を開始する時点で要求する．停止中は入力を処理しない．

### アクセシビリティ

PowerPointを遠隔操作しないMVPでは原則不要とする．将来必要になる場合は，機能を分離し，要求理由を明示する．

### ファイル

講義資料や出力先は，ユーザーが選択した範囲だけにアクセスする．

## 4．ローカル処理

ローカル音声認識とローカル板書判断を利用できる構造にする．ネット接続がなくても，少なくとも次を継続可能にする．

- PowerPoint取得
- 講師手書き
- 規則ベースの基本板書
- ローカル保存

## 5．クラウド処理

クラウドプロバイダは追加機能であり，初期状態では無効とする．有効化時には次を表示する．

- 送信先
- 送信するデータ種別
- 保存方針
- 利用目的
- 送信を停止する方法

可能な限り，音声そのものではなくローカルで確定した文字だけを送る．スライド全体ではなく，必要な文字とレイアウト情報だけを送る．

## 6．秘密情報

- APIキーはmacOS Keychainへ保存する
- `.env`，ソースコード，JSONセッションへ平文保存しない
- GitHub ActionsではGitHub Secretsを使う
- Pull Requestログへ秘密情報を出さない
- 実データを使ったデバッグファイルをコミットしない

## 7．ログ

標準ログに含めてよいもの：

- 処理時間
- 匿名のエラーコード
- フレーム欠落数
- 板書要素数
- モデル名と版

標準ログに含めないもの：

- 講義本文
- スライド画像
- 氏名
- APIキー
- 完全なファイルパス

## 8．学生発話

学生の音声を取り込む機能はMVPに含めない．将来追加する場合は，受講者への説明，同意，保存期間，削除方法を明確にする．

## 9．研究評価

実講義で性能評価する場合は，次を別途確認する．

- 研究倫理審査の要否
- 学生への説明と同意
- 教育目的利用と研究目的利用の区別
- 匿名化
- 保存期間
- 二次利用
- 著作権

## 10．配布

一般利用者向け配布では，Developer IDによる署名とApple notarizationを行う．更新機能を追加する場合は，署名済み更新のみを受け入れる．

## 11．脅威例

- 誤ったウィンドウを取得して機密情報を共有する
- クラウド設定が意図せず有効になる
- APIキーがGitへ入る
- 板書生成モデルが発話にない事実を加える
- 悪意あるセッションファイルが巨大データや不正パスを含む
- 自動更新経路が改ざんされる

各脅威に対し，対象選択UI，opt-in，Keychain，根拠検証，入力上限，署名検証で対策する．
